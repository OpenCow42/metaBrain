# Versioned wiki writes

A request to ingest, save, set up, edit, or repair authorizes the corresponding versioned writes within the selected project. A request to preview, inspect, audit, or plan is read-only. Ask only when the store, scope, or intended change cannot be determined, or when a separate destructive action is required.

Use the pinned store and connection from [the CLI skill](../SKILL.md). Read the wiki config and guides. For ingest and save, use an initialized wiki with a valid config, Markdown `index.md` and `_wiki/recent.md`, and room for a new document below `_wiki/operations/`. Use the setup skill for missing wiki structure. Report incompatible paths.

1. Read every existing note you will edit using `mb get PATH --format json`. Keep its `documentID` and `version` with the body you actually read. Record absence for planned creations and check for folder collisions. An operation input uses `path: {"rawValue":"..."}` and supplies `body`, `tags`, `metadata`, and `references`. Copy the existing title, tags, metadata, Markdown setting, and any other input fields you have read. Translate existing references from the read format as shown below. Preserve frontmatter and unrelated body content. Unspecified retention, Markdown opt-in, capture, claims, and source profile inherit from the current revision. Supply a complete claim list when editing it, preserving untouched claims and their IDs. An empty list clears claims.
2. Use one fresh UUID per logical change. Make focused additions to the existing index and recent summary without erasing custom text or unrelated entries. Add one new `_wiki/operations/<operation-UUID>.md` with date, purpose, and affected paths or links. Link to it from recent activity. When there is no substantive change, skip the navigation and log writes too.
3. Write a local temporary draft with `operationID`, `project: {"rawValue":"<root>"}`, and `documents` containing all changes together. Run `mb operation inspect DRAFT` with the pinned options. Compare every returned target version and ID with the observations from step 1, including absence (version zero, no ID). Verify the store path, store identity, project, and exact payload. If any target differs, re-read and replan on those actual revisions. Never substitute the newer expectations into the old draft. To cite a new note, use `creations[].documentID.rawValue` from a preliminary inspection for version 1, then reinspect the completed draft using the same UUID and recheck targets and IDs. Use stable block IDs or exact source headings, and use the retained reference returned or verified by native passage reads. For ingest and citation edits, run `mb operation inspect DRAFT --check-citations`. Check that each changed citation resolves to the intended document and that its returned passage contains the intended evidence. A marker in a draft is insufficient.
4. For a preview request, return the inspected changes, store, connection, and project. For a write request, apply the exact inspected file with `mb operation apply PREVIEW`. On conflict, reread and rebuild the draft from current versions if the intended edit is still clear. On an uncertain response, retry the identical preview to recover its receipt. Verify changed links with `mb links`, run scoped `mb lint`, and reopen the cited passages. Report changed paths and revisions, the receipt UUID, and any remaining findings. Keep operation notes append-only.

`get --format json` returns each native reference as `{"kind":"…","value":"…"}`. In an operation document's `references` array, use the corresponding form below with the original value.

| Read kind | Operation JSON |
| --- | --- |
| `documentID` | `{"documentID":{"_0":{"rawValue":"ID"}}}` |
| `path` | `{"path":{"_0":{"rawValue":"/virtual/path"}}}` |
| `externalURL` | `{"externalURL":{"_0":"https://example.org/"}}` |
