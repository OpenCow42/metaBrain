---
name: metabrain-wiki-ingest
description: Ingest supplied files or text into a metaBrain project wiki, preserving originals and relating their evidence to existing notes and claims.
---

Use the [CLI skill](../metabrain-wiki-cli/SKILL.md) to select the store and wiki. Follow [reviewed wiki writes](../metabrain-wiki-cli/references/reviewed-write.md) for inspection and apply.

1. Inventory the supplied originals locally. For inline material, write the supplied text verbatim into a local temporary UTF-8 file and record that origin. Compute SHA-256 of exact bytes and record the origin and media type. Treat the selected project, digest, and origin as the capture identity. Inspect existing source notes' `sourceCapture.blob.sha256` and `sourceCapture.origin`, including notes moved within the project. Lexical hits help find related notes and indexed claims, but cannot prove a capture is absent. Reuse a matching capture and note. The same bytes from a distinct origin can have a separate provenance note. Inspect exact destinations before proposing additions.
2. Draft source notes with faithful text and stable block IDs for cited passages. Record the extraction method only if one actually ran. For binary-only sources, keep the bytes and leave the source body empty. Use native search and verified links to find related notes, connect source drafts with them, and update the relevant claims. Identify which passages support and which contradict each claim. Keep competing accounts visible and use the contested state for unresolved disagreement. Use accepted only with fresh, active, non-synthetic support and no eligible contradiction, with two independent sources and distinct originals for high-risk claims. When evidence is inadequate, keep the conclusion provisional or unsupported. Never invent a quote, assessment, or independence group.
3. Show the intended originals, project, provenance, and document changes. For preview-only, use local inspection and an outline of the draft. Staging mutates the selected store, so skip staging in preview-only work. Otherwise obtain authorization before staging unless the user already requested actual capture. Stage only missing captures with `mb source stage FILE --origin ORIGIN --media-type TYPE` and optional `--extraction METHOD`. Verify the returned digest against the inspected bytes and use the returned object as the source note's `sourceCapture`. If the bytes changed, stop and review the new material.
4. Inspect the final operation with affected sources, notes and claims, project index, recent summary, and UUID log. Check it against the original observations and apply only the reviewed preview. If all inputs and resulting links and claims already match, leave the store alone and report the existing notes. Reuse the existing capture and claim IDs on repeat runs.
